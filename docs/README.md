# Docs (`docs/`)

Cross-cutting design docs for the whole `project3` workspace. For the operator
overview see the root [`../README.md`](../README.md); for the full technical
reference see [`TECHNICAL_GUIDE.md`](TECHNICAL_GUIDE.md).

| File | Topic |
|---|---|
| `TECHNICAL_GUIDE.md` | The complete module-by-module technical reference (gateway, agent core, DAG, skills, tools, channels, sandbox, computer use, Studio, reliability, security, cost, verification). |
| `ARCHITECTURE.md` | Module-by-module architecture deep-dive. |
| `ARIA_VS_HERMES.md` | Comparison notes (Aria vs Hermes). |
| `coding_harness_design.md` | The coding-harness (Studio) design. |
| `DOCUMENT_FORMATS.md` | Supported document formats and rendering. |
| `NEW_CHANNELS.md` | Survey + wiring plan for new (free-first) channels. |
| `NEXT_STEPS.md` | Roadmap / next steps. |
| `SLIDES_FROM_MARKUP.md` | Generating slides from markup. |
| `STUDIO_OPENCODE_PARITY.md` | Studio ↔ OpenCode parity notes. |
| `audits/` | Security/quality audit reports. |

## Conventions
- Root `README.md` = narrative overview; `docs/ARCHITECTURE.md` = design rationale;
  `docs/TECHNICAL_GUIDE.md` = exhaustive technical reference.
- Per-folder `README.md` files explain each code folder individually.
